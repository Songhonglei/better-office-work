### v1.4.0 (2026-10-16)

**新增 SS-CN8「节拍化人味」（反向模式）+ SS-CN7 补录「基线方向核对」**

两处都来自同一批稿子的复盘：两篇同作者的公众号历史科普长文（《拿破仑帽子》《佛像》）。
共同症候不是「AI 味重」，而是**「人味太规律」** —— 这一形态在 v1.3.1 的五类里全部漏判。

**Added — SS-CN8 节拍化人味（反向模式）**

- 新增第八条表面信号，也是目录里**唯一的反向信号**：其余各条抓「太机器」，这条抓**「太像人」**。
  本该随机的口语标记以固定间隔复现，读者读到第三段就能预判下一句要抖包袱 —— **规律性本身成了新指纹**。
- 五条子信号：8a 段尾俏皮句节拍化 / 8b 每节必收束 / 8c 招呼式称谓过载 / 8d 同构三连排比 / 8e 模糊限定词过载。
- 适用范围**仅长文与文学档**：短文本本来就该塞语气词，「节拍」无从谈起。
- `preflight-check.py` 新增 `[SS-CN8]` 区块（`long` / `literary` 档自动输出，`short` 档不出）。
- `SKILL.md`：Genre Gate 两档适用信号、Mode A 第 4/5/7 步、类别表（SS-CN1~SS-CN8）、新增「检查三」、Edge Cases 两条。
- **修法方向反直觉**：命中它时不要说成「AI 味重」，要说「人味太规律」；改法不是**再加**人味，而是**做减法**。

**Fixed — SS-CN7 补录「基线方向核对」**

- 原 SS-CN7 只教「数半角引号，应为 0」，**没教先确认这 N 处的来源**。
- 实测踩坑：原文标点层全 0（全角 12 / 半角 0），用 Write 落成 `draft-*.md` 之后变成**全角 0 / 半角 12**。
  不核对方向，会把一篇 0 缺陷的稿子报成 12 处 FAIL，并顺着「修」出 12 处假改动 —— 即**转录污染**。
- 脚本新增 `全角引号 “ ”` 计数行与 `baseline_note()`：命中「全角 0 且半角非 0」时在表头打
  `!! 基线核对（SS-CN7）：…`；「两种引号并存」时提示半角那部分才是真残留。

**标定过程（为什么 8a 故意不设阈值）**

- 拿四篇真实稿子标定，8a 的阈值怎么取都不可靠：20 字宽限会把
  「布袋和尚这条线，跟中国十世纪的一位僧人有关」这种普通中句一起算进来，
  于是**改得更好的稿子占比反而从 24% 涨到 35%**。
- 结论：8a 只报原始数字（例 `24 / 56 = 43%`），判据留给人工 ——
  「读一遍，若每段结尾都能预判要抖包袱，就是命中」。**假精确比没有数字更坏。**
- 8c / 8d / 8e 的阈值（5 / 8 / 8）在两篇已判定「节拍化」的稿子上均正确触发，在未命中的《佛像》原稿上未触发。
  8d 计数会虚高约三成（「掏钱、干活」这类顿号词组被当成并列项），所以限放到 8。
- 8b（每节必收束）**不做机械计数** —— 「节末收束」与「正文本来就短」在数字上无法区分，硬做只会造出假精确。

### v1.3.1 (2026-10-11)

**修复：`preflight-check.py` 行锚定检查的三处同源缺陷（1 漏判 / 2 误判）**

根因是一个：**行级匹配前没有先剥掉 Markdown 标记**。`## ` / `> ` 自带的空格既不是「标点周边空格」，
标题里的编号也不是正文编号，于是同一个缺陷在三个地方各发作一次。

- **修 ①（漏判，假 OK）「编号式小标题」数不到带 `## ` 前缀的编号标题。**
  原正则锚定 `^\s{0,6}`，匹配不上 `## `；`## 01 开场` / `## 一、开场` 全部漏报，
  基线会打出「0 / OK」这种**假 OK**。现改为先剥标题标记再匹配。
- **修 ②（误判，假 FAIL）`## “引言式标题”` 被判「标点周边空格」。**
  命中 `[ \t][（【“‘]` 的那个空格其实是 `## ` 自带的。此前在「」体例下长期隐形
  （正则字符类不含 `「」`），正文一改用全角双引号 `“ ”` 就立刻冒出来。
  同类还有 **`> ——来源` 被判「破折号前后带空格」** —— 引用块标记的空格同样不是违规。一并修。
- **修 ③（漏判）** 「编号式小标题」漏判**独占一行的裸汉字编号**（`一`／`二`）。
  原正则要求编号后必须带顿号或句点，散文／回忆录里独占一行的段落编号一个都数不到。
  新增分支 `[一二三四五六七八九十]{1,3}[ \t\r]*$`。
  **注意：修脚本是为了如实报数，不是为了自动删编号** —— 汉字段落编号在散文里是常态，
  该不该留由作者定；脚本只负责不再假装看不见。
- 实现：新增 `strip_md_markers()`，剥掉行首 `#{1,6} ` 与 `> `；
  「标点周边空格」「破折号前后带空格」「编号式小标题」三项改在剥离后的副本上匹配，
  其余检查（半角引号计数、段落切分、R 类统计）仍用原文。
- 同时把编号正则的 `^\s{0,6}` 收紧为 `^[ \t]{0,6}` —— 原写法里的 `\s` 能吃掉换行，锚点会漂移。

### v1.3.0 (2026-09-27)

**新增：改写后的验证闭环（postflight）+ 自检脚本**

- **Mode B 新增第 5 步「Re-run the mechanical checks on the rewrite」** —— 此前检查层只前置、不闭环，
  改造后要求对**改写稿**重跑标点层（文学/抒情档加跑 R 类），**把复测数字写进回复**，FAIL 项不归零不得交付。
  起因：v1.2.1 流程下《长城》稿改写后残留 12 处半角引号，漏到交付环节——
  SS-CN7 是本 skill 自标「优先级最高」的一条，却踩在了自己的流程上。
- **新增 `scripts/preflight-check.py`** —— 一条命令输出标点层 / 排版 / 人称 / R 类全部统计项。
  结果**分 FAIL / WARN / INFO 三级**：机械残留判 FAIL 并决定退出码，文风项（超长段、同位语密度、词库命中）
  只判 WARN——避免脚本逼作者把散文剁碎。此前全流程靠人肉数，2000 字以上长文必然漏。
  支持 `--tier short|long|literary` 档位感知、`--lyrical`、`--para-max`、`--strict`、`--cut`、`--json`。
- **脚本新增语言护栏 `--lang auto|zh|en`** —— 标点层规则是中文专属的（半角引号、`...`、`--` 在英文里
  本来就是正确写法）。auto 模式先按 SKILL.md 的 Language Auto-Detection 口径算 CJK 占比，
  不足 50% 就把标点层降级为 INFO、不参与退出码并打出警告，避免有人拿它审英文稿得到一堆假 FAIL。
  需要覆盖时显式传 `--lang zh`。
- **「检查一 · 标点层」标题改为「跑两次」** —— 明确「审计前定基线 + 改写后做验收」两次调用，
  并注明长文必须用脚本、不可目测。
- **SS-CN7 补「改完必须复测」** —— 附实测数据（20 处 → 残留 12 处），说明「顺手换」只换掉一部分，
  残留量与原文同量级。
- **Mode B 第 3 步补交付形态建议** —— 长文（公众号正文、署名文章）直接产出定稿文件 +
  分隔线后的「本轮改动」清单，不要在对话里贴 2000 字。
- **Edge Cases 补「事实层」分工说明** —— 本 skill 不管事实核查，但改写时要顺手做两件事：
  不改动事实本身（数字 / 人名 / 时间 / 引语照写，存疑处标注给作者）；作者无法自证出处的细节
  **不删、不替换**，加「据说」或交代来源。两个高频动作：日期模糊化、无出处数字加「据说」。

### v1.2.0 (2026-09-26)

**新增：文学 / 抒情体裁支持 + 体裁闸门**

- **新增 `references/lyrical-appositive.md`** —— 抒情同位语正反对照例句库。含「公共喻体 vs 私人喻体」对照、三问快速判定（删掉形容词还剩什么 / 换个作者还能不能用 / 同一段意象能否挂到同一场景）、把同位语还原成叙述的改写示范，以及一个真实案例：抒情同位语里藏着「21 年误写成三十年」的事实硬伤。
- **`references/ai-smells-cn.md` 新增第六类：修辞与抒情信号 R-CN1~R-CN6** —— 对映「AI 抒情同位语仿写检测清单」：同位语过密、句式僵化无变体、陈腐喻体词库、万能形容词冗余、意象不统一、抒情无落点（R-CN6 其余体裁同样适用）。附**文学体裁快速筛查**：命中 5 条中任意 3 条即 🔴，**不用 smell 计数** —— 抒情文本单点致命，计数式会漏判成 🟢。
- **新增 R 类机械自检** —— 同位语结构计数（`X，Y 的 Z` 出现次数 / 最长连续句数 / 单段峰值）+ 陈腐喻体词库与万能抒情形容词词库命中计数。与标点层并列，**先出数字再谈文风**。
- **`SKILL.md` 新增 Genre Gate（体裁闸门）** —— 短文本 / 长文 / 文学三档，分别规定适用信号与改写规则。此前只有一条「长文降级」注释挂在改写规则下方，**检测层没有同步**，导致同一份 skill 对不同体裁给出互相打架的建议。
- **修正 SS-CN5 与 SS-CN7 的循环冲突** —— 原 SS-CN5 说破折号 `——` 是 AI 信号、应改逗号，SS-CN7 说 `--` 应统一成 `——`，两条规则闭环抵消。现明确分工：SS-CN7 管**形态**（统一成 `——`、前后不加空格），SS-CN5 只管**留不留**（且仅限短文本）；长文与文学档破折号是正当的叙事工具，只做控量与规范化。
- **改写黄金规则加档位标注** —— 第 2、3、8 条限定短文本；新增第 9 条「文学档只做减法」（不要用新喻体替换旧喻体，不要为「人味」加错字或语气词）。
- **Edge Cases 补充** —— 「抒情短句不算短」例外（九个字的 `黄昏，大地温柔的信使` 正是要抓的形态）、文学 / 诗体输入路由、中英混排空格例外。
- **description 补体裁触发词**（散文、美文、文艺腔、抒情段落、现代诗短句、小说叙事段落）—— 此前触发词全指向社交平台，写散文时根本触发不到本 skill。
- README 由模板占位（`One-line description here` / `Feature 1`）补为真实内容。

### v1.0.0 (2026-07-28)

- Initial open-source release
