# 中文清晰表达与风格参考

本目录用于编辑诊断，不用于作者来源判定或审核预测。以下现象只有影响阅读或不符合作者目标时才需要修改；不设命中数评分。保留事实、引语、引用、链接和必要披露。

## 结构与信息顺序

- 开头重复标题或空泛铺垫：把读者需要的信息前移；背景确有帮助时保留。
- 分点内容重叠：合并重复观点，重新安排顺序。步骤、清单、编号标题都可保留。
- 编号小标题的取舍：技术文档、步骤说明适合「01/02/03」「首先其次最后」骨架；公众号署名长文若作者偏好口语化节奏，可主动建议拆除编号骨架，改为概括性标题或自然过渡。这是文风选择，按作者目标执行，不是纠错。
- 引用后回复：保留准确引文与来源，区分作者意见。逐条回应适合澄清争议，无须强改为闲聊。
- 长文层次：标题应概括本节内容；引言、论证、总结可以完整存在，不能为追求随意而破坏逻辑。

虚构的编辑示例（不代表作者经历）：

> 原句：首先需要做好备份工作，其次需要完成备份工作后的核验工作。
>
> 改句：先备份，再核验备份结果。

## 语气与立场

「作为……」「确实」「有道理，但是……」本身没有问题。仅在身份说明无关、套话掩盖具体意见或转折关系不清时调整。不编造身份或经历，不把「我们」自动改成「我」；先确认实际指代。

平衡分析、保留意见和明确结论都允许。保留原文证据强度：「可能」不能变「必然」；不能添加假犹豫，也不能强迫作者站队。专业文稿可保持书面语，社交短文可按作者偏好口语化，不强制加语气词。

## 冗余与措辞

- 连接词说明真实关系时保留；同一段重复「与此同时」而无新关系时可删。
- 「关键在于」后应有明确内容；改写要澄清结论，不能只换成另一句口号。
- 多个例子若各自承担不同证据作用就保留；删重复例子不能损伤证据链，不能换成编造亲历。
- 术语可中英混排，照顾读者理解。不得把英文片段里的 apostrophe、半角引号或代码标点当中文格式错误。
- 功能清单适合产品说明，叙事适合经历分享；根据用途选择，不能把产品事实变成未提供的使用感受。

## 收尾与阅读节奏

总结应与论证相称。开放提问、鼓励或抒情结尾可以保留；只修改空泛、重复或与主题无关的部分，不强制戛然而止。

句长、段长和排比取决于信息负担。可拆解难读长句，也可合并过碎的短句。语法正确、没有错别字是正常目标，不注入错误或所谓真人痕迹。

## SS-CN7 · 排版观察

此代码保留供历史检索，现仅表示排版观察。中文正文可根据选定体例统一引号、省略号、破折号和空格；半角标点不能推断来源。标题、列表和破折号都允许。

先确认引语、代码、URL、英文片段和引用区域。引文默认不改。全角与半角引号的比例不能判断转录污染，只有与原文件或可靠来源逐项对照才能确认差异。

### 体例统一清单（用户选定该体例后执行）

以下六条是用户显式选定「格式统一」润色时的标准动作；未选定时不主动全篇替换，只作诊断提示。

1. **人物译名**：外国人物译名采用主流通行译法（以通行出版物、权威媒体的译名为准），全文同一人物保持同一译名；拿不准时在编辑说明中标「待核实」，不生造译名、不混用两种译法（如「凯撒 / 恺撒」二选一后全篇统一）。
2. **间隔号**：人名、译名中的分隔符统一为中文间隔号「·」（U+00B7），不使用片假名中点「・」（U+30FB）或半角「.」。例：「奥诺雷·德·巴尔扎克」「史蒂夫·乔布斯」，多层姓名每段之间都用「·」。
3. **引号**：中文正文的半角直引号（`"` `'`）统一为全角引号——外层双引号「""」，引号内再引用用单引号「''」；代码、URL、英文片段、代码块和原样保留的引文不参与替换。
4. **引号配对**：替换后逐对核对前后引号匹配，重点排查替换产生的「两个连续前引号」「落单后引号」「跨段错配」；以脚本计数核对残留量，不凭印象宣称已清零。
5. **多余空格**：删除中文与中文标点之间的冗余空格，如「10月13 日」「是"史家之绝唱"。 一部史书」中数字/标点旁的空格；中英文、中文与阿拉伯数字之间的空格按全文既定体例统一——留则全留、删则全删，不混用。
6. **书名号并列**：《XX》《YY》之间不加顿号，直接并列（如「《史记》《汉书》」）；此为现行标点用法规范的推荐写法，全篇统一执行。

默认不自动全篇替换；当用户选定上述体例时按清单执行，并在改动说明中逐条报告执行结果。

[scripts/preflight-check.py](../scripts/preflight-check.py) 默认把候选格式差异作为可选建议；只有显式 `--strict --check ...` 才约束所选项。`--lang auto` 采用 CJK / (CJK + Latin) **>50%**，等于 50% 不启用中文标点约束。

## SS-CN8 · 节奏观察（长文 / 文学）

旧名及来源判定含义已废弃。该区块现全部为 INFO，没有 WARN/FAIL 阈值，严格模式也不阻塞。词频既不等于冗余，也不反映作者来源。

| 统计 | 当前口径 | 人工复核 |
|---|---|---|
| 段尾短句数与占比 | 末个含至少 2 个 CJK 的句段不超过 20 个 CJK | 20 只是读数分组，不是优劣阈值；查看收尾是否重复信息 |
| 称谓词频 | 咱们 / 大伙儿 / 人家，分别及合计 | 指代是否清楚，是否符合作者语气 |
| 限定词频 | 确实 / 自然 / 实在 / 其实 / 恐怕 / 大概，分别及合计 | 有无证据强度变化，不能机械删除不确定性 |
| 多逗号短句粗计 | 至少 2 个逗号或顿号、CJK 数不超过 22 的句段 | 22 只是统计口径，词组并列也会被计入，脚本不识别语法同构 |
| 小标题节数 | Markdown ATX 标题数量 | 判断层次是否清楚，不推断「每节必收束」 |

段落按空行划分，同一段内软换行合并；标题、列表、表格、引用不算正文段落。旧版 5/8/8 等质量阈值缺乏充分依据，全部移除。没有词语黑名单，不要求删到某个次数。

## 体裁与平台适配

短文聚焦问题，长文保留层次，文学关注意象与叙事（见 [rhetoric-cn.md](rhetoric-cn.md) 和 [lyrical-appositive.md](lyrical-appositive.md)）。同一个平台允许多种文风，不设统一句数、错字量、语气词量或过审标准。当前字数、格式或披露要求如有需要应另行核实，不能凭本参考断言。
