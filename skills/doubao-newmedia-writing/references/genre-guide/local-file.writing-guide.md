# 本地文件交付（创建 Markdown + HTML）

本文件负责新媒体写作任务的本地文件创建与写入。进入本技能后，先在 `output/` 下建一个独立输出目录和 Markdown 源文件，再按命中的创作类型 guide 与 samples 把文本、图片和排版写入文件，最后生成一份可直接在浏览器打开的 HTML 排版页。

## 交付目标

1. 每次任务创建 1 套交付文件：`主题.md`（源文件，可继续编辑）+ `主题.html`（排版页，可预览/复制/发布前检查），放在同一个独立输出目录内。
2. 所有交付物写入**当前工作区的 `output/` 目录**下，不写工作区根目录，不散落到 skill 目录。
3. 每个创作类型的交付物都同时包含文本内容和图片内容/图片落位。
4. 最终回复给出 .md 和 .html 的真实文件路径；如当前环境支持预览，主动展示 HTML。

## 输出目录与文件命名

在 `output/` 下建本次任务的独立目录，目录名用「时间戳_主题短名」，避免多任务互相覆盖：

```
output/20261116-172500__通勤咖啡杯测评/
├── 通勤咖啡杯测评.md          # Markdown 源文件（文本 + 图片相对路径）
├── 通勤咖啡杯测评.html        # HTML 排版页（浏览器可直接打开）
└── images/
    ├── cover.png              # 封面图
    ├── note-01.png            # 正文配图/分镜图
    └── ...
```

命名规则：
- 目录：`YYYYMMDD-HHMMSS__主题短名`（短名去掉标点、空格，不超过 20 字）。
- 文件：`<主题>.md` / `<主题>.html`，主题与标题一致。
- 图片：统一放 `images/`，用语义名（cover / note-01 / shot-03），Markdown 与 HTML 都用相对路径引用。

## 文件创建与写入

用文件工具直接创建和写入，不依赖任何外部 CLI 或在线服务：

1. **先建占位**：按「创建顺序」生成标题后，用 Write 创建 .md 文件，写入一级标题和一行最小占位说明，确认文件已落盘、可读。
2. **持续写入**：平台主干每完成一个稳定模块，就用 Edit 把该模块追加进 .md 文件；内容较长时分多次写，避免单次过大。
3. **修改已有内容**：需要替换时用 Edit 精确替换对应段落；不推翻整篇重写。
4. **图片落位**：在 .md 中对应位置写相对路径图片引用 `![说明](./images/cover.png)`；图片未就绪时先写占位行 `> [图片待生成] 封面图｜提示词：...`，后续生成成功再原位替换。
5. **生成 HTML**：文本与图片全部写入后，按「HTML 排版页生成」把 .md 渲染成 .html，与 .md 放同目录。

## 创建顺序

1. 识别创作类型：确认本次是小红书、公众号还是短视频脚本。
2. 生成标题：用「平台 + 主题 + 内容类型」，如「小红书图文笔记｜通勤咖啡杯测评」「公众号文章｜AI 工具使用边界」「短视频分镜脚本｜新品发布 60 秒」；标题唯一，不与正文开头重复。
3. 先建最小占位：首次创建 .md 只写标题和占位行，确认文件已落盘，平台分区和排版由命中的 guide 与 samples 接管。
4. 路由创作类型：按用户明确选择读取对应平台主干 guide，再由平台主干读取排版 samples，按其分区顺序把内容写入同一个 .md 文件。
5. 持续回写：平台主干每完成一个稳定模块就追加写入 .md。
6. 生成 HTML：全部内容写完后生成同目录 .html 排版页。

## 骨架模板来源

本节标明各创作类型的文件内排版来源。先建最小占位拿到文件路径，再按命中类型的主干 guide 和排版 samples 写入。

### 小红书图文笔记

读取 `xhs.writing-guide.md`，并由其读取 `../xhs.samples/xhs-note-proposal.samples.output-format.md`。完整图文结构以该文件为准，核心顺序为：

1. 笔记标题。
2. 笔记配图。
3. 正文内容。
4. 直接复制版本。
5. 标题备选。
6. 话题标签备选。
7. 封面设计灵感。
8. 评论区互动引导。

配图数量、图片分栏、发布版正文纯净规则和局部需求压缩方式，均以小红书排版 sample 为准。

### 公众号文章

读取 `wechat.writing-guide.md`，并按需读取 `../wechat.samples/Layout-and-illustration-requirements.md`。完整文章结构以公众号主干和排版文件为准，核心顺序为：

1. 正文。
2. 封面图。
3. 备选标题。
4. 内容验真。

头图、正文、小标题、自然段、文中配图、重点句和结尾排版，按公众号排版文件自动匹配文章类型与风格。

### 短视频分镜脚本

读取 `short-video.writing-guide.md`，并由其读取 `../short-video.samples/output-format.md`。完整脚本结构以该文件为准，核心顺序为：

1. 项目概览。
2. 创意策略。
3. 完整标准 7 列分镜表。
4. 封面方案区。
5. 视觉参考区（关键分镜图）。
6. 拍摄执行包。
7. 剪辑提示。
8. 平台适配。
9. 合规与风险提醒。

分镜表字段、视觉参考区、封面方案、拍摄执行包和写入前检查，均以短视频排版 sample 为准。

## Markdown 结构原则

- 文件只设 1 个主标题（H1），正文开头不重复标题。
- 信息层级用 H1/H2/H3、正文、表格、清单、引用块承载；只有确需对比、流程、拆解或执行清单时才用表格或结构化块。
- 平台内排版按对应平台 guide 与排版 samples 执行，各平台保留差异化排版。
- 需要图片、封面、视觉参考或素材占位时，先在 .md 建立明确位置（相对路径图片行或占位行），再由对应平台流程补充。
- 文件结构服务当前创作类型，同一模块只承载命中的平台内容。

## 搜图与生图落位流程

图片、封面、视觉参考图、分镜图与文本一起构成完整交付物。

1. 按命中类型 guide 写入时建立图片区、封面方案区或视觉参考区，写清用途和对应模块。
2. 搜图或生图成功后按平台排版原位写入：
   - 本地生成/下载的图片：存到 `images/`，在 .md 对应位置写 `![说明](./images/xxx.png)`。
   - 网络图片：优先下载到 `images/` 再引用；确实无法下载时可直接写 `![说明](https://...)`，并在交付说明中提示外链可能失效。
3. 图片工具、搜图或生图暂不可用时，在原位写占位行 `> [图片待生成] 用途｜提示词：...`，保持文件完整可交付。
4. 落位规则：小红书配图进「笔记配图」区；公众号封面图或配图进正文、封面图或封面方案区；短视频封面图进封面方案区，关键分镜图进视觉参考区对应镜号。
5. 图片按对应模块原位回填；最终 .md 与 .html 中的图片区、封面方案区或视觉参考区保持完整。
6. **图片纯净闸门**：入文件前逐张确认无规格文字、尺寸标注、平台字样、风格标签、作者水印、二维码、模型签名等；顶部和底部边缘无残留小字。问题图先裁切/重绘并复检，无法干净修复就重生成，禁止带病交付。

## HTML 排版页生成

文本与图片写入 .md 后，生成一份自包含的 HTML 排版页，规则：

1. 与 .md 放同一输出目录，文件名同名 `.html`。
2. 单文件自包含：CSS 内联在 `<style>` 中，不引外部样式表/字体/CDN，断网也能打开。
3. 图片一律用相对路径 `images/xxx.png`，确保同目录整体移动后仍可显示。
4. 用简洁、克制的排版：居中正文容器（最大宽度约 720px）、清晰标题层级、表格边框、引用块样式；小红书配图用 CSS Grid 分栏并排（每行 2–3 张），禁止单列平铺。
5. 响应式：窄屏下配图自动降为 1–2 列，表格可横向滚动。
6. 不含任何系统提示、内部术语、文件名或思考过程；页面只呈现成品内容。
7. HTML 交付前自查：浏览器可直接打开、图片全部加载、分栏正常、表格不溢出。

## 创建恢复流程

按顺序恢复，保持本地文件交付通道：

1. 路径不可写/目录创建失败 → 确认当前工作区可写、`output/` 存在（不存在就先建），换用更简单的目录名重试。
2. 文件写入失败或内容异常 → 检查文件是否已被创建、是否非空，必要时重建占位后分段写入。
3. 标题重复或文件已存在 → 微调主题短名或时间戳，确保目录与文件名唯一，不覆盖已有交付物。
4. 图片生成失败 → 原位保留占位行与提示词，继续完成文本部分，并在交付说明里注明图片待补。
5. HTML 生图/渲染失败 → 保证 .md 完整交付，说明 HTML 缺失原因和补生成方式。
6. 任何环节持续失败 → 暂停下游创作路由，说明具体卡点和下一步恢复方式，不交付半成品当成品。

## 交付前验证

最终回复前确认：

1. .md 与 .html 两份文件都已落盘、非空、路径真实可访问。
2. 命中的创作类型主干已把内容写入同一份 .md 与 .html。
3. 对应平台核心排版区块已出现：小红书图文分区、公众号正文与验真区、短视频 7 列分镜表。
4. 文本与图片均已原位体现：成功图片、图片占位或生成/搜索提示词至少一种存在；HTML 中图片相对路径正确。
5. 需要核对写入结果时直接读取 .md / .html 检查结构；发现缺块、错位或图片未落位先修复再交付。

## 最终回复

- 成功：`已完成：<文档标题>。Markdown：<路径>。HTML 排版页：<路径>。包含：<一句话列出主要模块>。`
- 受限：说明具体卡点、已完成内容、已落盘的文件路径和可继续处理的下一步。
