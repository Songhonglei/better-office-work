# story.json 结构

一本书一个 JSON，放在 `stories/<slug>.json`。`build_site.py` 会遍历 `stories/*.json`（跳过 `_` 开头的文件）生成书架。

## 顶层字段

| 字段 | 用途 | 说明 |
|---|---|---|
| `slug` | 目录名 | 图片在 `assets/images/<slug>/`，站点在 `site/read/<slug>/` |
| `title` | 书名 | 阅读页标题、导航 |
| `book` / `author` | 出处 | 阅读页副标题 |
| `source` | 版权说明 | 写「公有领域」 |
| `era` | 朝代 | 只做标注，实际装束约束在 `era_anchor` |
| `style` | 风格文件名 | 对应 `styles/<style>.txt` |
| `summary` | 一句话简介 | 首页卡片与 meta description |
| `cast` | 人物表 | **配角也必须在这里**，见下 |
| `era_anchor` | 朝代装束约束 | 每页都会拼进 prompt |
| `pages` | 分页数组 | 第 0 页固定是封面 |
| `colophon` | 版权页 | 可选 |

## cast：人物锚点

`make_prompts.py` 决定这一页要拼进哪些人物锚点，有两条路：

- **显式**：页面写 `"who": ["王七", "道徒"]`，脚本逐个校验是否在 `cast` 里，缺一个直接报错退出；
- **隐式**：不写 `who` 时按子串匹配 `[c for c in cast if c["name"] in page["scene"]]`。若只匹配到 1 个锚点、而 `scene` 里又出现「道徒 / 师兄 / 妻子 / 众人」这类称谓，脚本会在 stderr 打印提醒——这是「配角穿主角衣冠、长主角的脸」的根因，宁可吵一声也不要静默通过。

由此推出两条硬规则：

1. **凡是在 `scene` 里被点名的角色，`cast` 里必须有同名的锚点**。场景写「道徒」而 `cast` 里没有「道徒」，这一页就只有主角一个锚点，拼 prompt 时「所有人脸型差异极大」那句也不会出现——模型会把配角画成主角的同款脸、同款衣冠。
2. **锚点里写死颜色与冠帽**。只写「穿交领宽袖长衫」不写颜色，模型会自作主张换色；只写「戴巾」不写「深黑方巾、不是浅灰包头布」，十有八九给一块灰布。

锚点建议结构（顺序固定，越靠前权重越高）：

```
年龄 + 脸型 + 面色 + 眉眼 + 胡须（明确有无）
+ 冠帽（颜色、形制、否定项）
+ 衣（颜色、形制、袖宽、下摆长度、腰带、鞋）
+ 身份特征（手粗、书箱、拂尘……）
```

主角与配角的相貌要用**成对的反义句**写，例如：

- 主角：白面无须的年轻书生，细眉小眼、下巴略尖
- 师兄：黑红脸膛的中年人，浓眉、短须、脸宽

## pages：分页

| 字段 | 说明 |
|---|---|
| `no` | 0 = 封面，1..N 正文。图片文件名按 `%03d` 对应（`000.jpg`…） |
| `kind` | `cover` / `page` |
| `title` | 页标题，两到四字，出现在阅读页左侧目录 |
| `caption` | 说书人旁白。口语、第一人称或说书腔，一到两句，结尾留钩子 |
| `scene` | **给模型看的画面描述**，不是给读者看的。见下 |
| `who` | 可选。这一页出现的角色名数组，写了就按它拼锚点并校验；不写则按 `scene` 子串匹配 |

`scene` 要写全七件事：

1. 时间与光（黄昏/夜里，光只照亮哪一片）
2. 谁在哪（左/右、前/后、隔多远）
3. 在做什么（动作要能画出结果，不要写心理活动）
4. 看哪里（**必须有明确注视对象**，否则模型默认看向镜头）
5. 手里有什么、有几件（数量写死，见 playbook 第 28 条）
6. 周围陈设（家具、器物、门窗、地面）
7. 明暗落点（重色压在哪、人物保持素白）

## 一本书 20 页的结构（实测可用）

- 0 封面
- 1—2 起：动机与环境
- 3—5 入：拜师、受挫、日常
- 6—8 承：三个日常段落，每个埋一处伏笔
- 9—12 转：奇观段落（视觉高潮，两到三页连排）
- 13—16 折：求术、告诫（因果钥匙）
- 17—19 合：回家、应验、收束

伏笔要能回收：本任务里「怕苦 → 辞归」「手茧 → 月暗」「告诫 → 撞壁」各回收一次。
