# 发布链路行为清单（video-multi-release）

**加载时机**：要确认「脚本到底做不做某件事」时，或排查「为什么没按预期执行」时。
日常照着 `SKILL.md` 的快速开始跑即可，不需要读本文件。

本文件描述的是**当前代码行为**（`scripts/release.sh` 与三个 `.mjs`），不是设计意图。
改行为必须同步改这里。

## v1.4：发布前质量与结果记录

进入浏览器前，若视频目录已有 `quality_report.json`，必须 passed 且视频哈希匹配，
项目的时间轴／脚本存在时也须匹配。新 `production.json` 项目缺失报告会拒绝发布。
`QUALITY_REPORT` 可显式指定报告路径；独立旧视频无报告时兼容原行为。
失败为 `E_QUALITY_GATE`、exit 10。检查在自动压缩之前针对源成片进行；
自动压缩属于既有派生上传步骤，不声称派生文件做过逐条字幕像素核验。

每个平台执行后，向实际上传文件目录追加 `publish_log.jsonl`，记录模式、状态、退出码、
URL 和实际文件哈希。该记录不把 stage／draft 当成 published，也不替代后台作品核验。

## 1. 体积与自动转码

`release.sh` 在参数校验阶段读视频体积：

| 条件 | 行为 |
|---|---|
| `MAX_VIDEO_MB`（默认 **40**） | 超过就转一份 `final_web.mp4`（与源文件同目录）再发 |
| `MAX_VIDEO_MB=0` | 关闭转码，直接发原件 |
| 压缩版已存在且**不比源文件旧** | 复用，不重转 |
| 压缩版比源文件旧（`-nt`） | **重转**，避免换片后仍发旧压缩版 |
| ffmpeg 失败 | `E_TRANSCODE_FAILED`（exit 10），`what_now` 给手动命令与跳过开关 |

转码参数：`libx264 -preset medium -crf 24 -maxrate 2600k -bufsize 5200k`。

**为什么默认 40**：视频号上传有 160 秒硬超时，78MB 原件必然超（同文件小红书 83 秒能过）。
25MB 版本 18.6 秒传完，抽帧看画质无明显差异。

## 2. 上传完成判据（平台各不同）

上传完成 ≠ 编辑页出现。三家的判据都不一样，**不能互相套用**。

| 平台 | 主判据 | 辅助 / 反例 |
|---|---|---|
| 小红书 | 「重新上传」文案 **和** 标题输入框**同时**出现（轮询约 2 分钟） | 别用 `video` 元素数量——页面可能有 4 个（预览/封面候选） |
| 视频号 | 「发表」按钮可用 **且** `video.duration > 0`，两个都要 | 单看 duration 会误判：本地文件解码立刻有值，实测卡在 14%/90% 时已 `>0` |
| 抖音 | 「上传中 / 正在上传 / 取消上传 / xx%」**全部消失**，且至少过了 4 轮 | 抖音没有「重新上传」这种信号；出现「上传失败」立即报错，等不到报 `E_UPLOAD_NOT_FINISHED` |

## 3. 发布后核验

| 平台 | 核验方式 | 失败处理 |
|---|---|---|
| 小红书 | URL 含 `published=true`（主判据） | 未确认 → `E_PUBLISH_UNCONFIRMED`(80) |
| 视频号 | 回列表 shadowRoot 查标题 | 查不到**只告警**（列表可能不显示短标题），OK 块输出 `verified: manual` |
| 抖音 | **回作品列表**确认标题出现 + 读作品数 | 查不到 → `E_PUBLISH_UNCONFIRMED`(80)。**不再只看 URL 跳转** |

**视频号 45 秒没跳转不再兜底重复点「发表」。** 早期版本会「再点一次」，第一下其实已提交时会双发，
现在只等待，交给列表核验。

## 4. 话题

| 行为 | 说明 |
|---|---|
| 挂不上只告警、继续发布 | 输出 `topics_missing: <列表>`，不因话题失败终止整条发布 |
| 抖音话题循环幂等 | `RESUME` 时只核对已挂标签，**不重插**（早期会往描述末尾重复追加） |
| 抖音话题必须回车 | 输入 `#话题名` 后 `Enter`，下拉首项即精确匹配；`el.click()` 无效 |
| 补挂失败别用退格 | 标签是整体单元，连按会连已挂的一起删（实测误删 `#历史真相`），宁可留成纯文本 |

## 5. 现场复用（SPACE_ID / RESUME）

| 情况 | 行为 |
|---|---|
| `SPACE_ID=N` | 在**那个空间里重跑全流程**，不是「接着填」。已在编辑页则跳过上传和重复填表 |
| `RESUME=1` | 同上，跳过 `Page.reload`（抖音 reload 会杀掉扫码登录态） |
| `MODE=publish` | **强制忽略 `SPACE_ID`**，防止拿旧现场重发造成双发 |
| 普通重跑（无上述变量） | 开头 `Page.reload`。**抖音用户扫码后不要这样重跑** |

⚠ `SPACE_ID` 复用只适用于「空白现场」（空间里还停在登录页）。
如果旧页面已上传过视频、填过内容，再投递文件会撞 `E_UPLOAD_TIMEOUT`(30)，必须清理后用新空间。

## 6. 三种收尾模式

| 模式 | 行为 |
|---|---|
| `stage` | 内容就位后停住，不提交、**不释放 space**（需手动 `completeTaskSpace`，否则常驻） |
| `draft` | 小红书/视频号走各自草稿；**抖音无可靠草稿箱，退化为 stage** |
| `publish` | 真提交，并做发布后核验 |

## 7. 汇总与退出码传递

- 每个平台显示 `发布状态`、`url`、`核验=`、`未挂话题=`。
- **必须有 `=== OK (...) ===` 块才算成功**——没有 OK 块即使子进程返回 0 也判 90。
  早期 bug：退出码 0 但脚本根本没跑完（stage / draft / 卡死）都被汇总成「✅ 成功」。
- 默认**第一个平台失败就停**，`break` 掉后续平台，避免三个平台状态各不相同、排查成本翻倍。
- `CONTINUE_ON_FAIL=1` 时继续尝试，末尾汇总；**整体退出码保留第一个失败平台的码**（`FIRST_FAIL_RC`），
  不会因为后面成功而重置为 0。

## 8. BGM

- `mix_audio.py` 里 BGM 短于成片时自动 `-stream_loop -1` 循环。
  实测 `Frost Waltz` 只有 135.5s，曾让 158s 的片子片尾静音。
- 曲库全部 CC-BY 4.0，`release.sh` 运行时会打印署名提醒。**提醒不代表来得及改**——
  写 `DESC` 的当下就该带上 `Music: 作者 (CC-BY 4.0)`。

## 9. 配置（数据目录 config.json）

位置：`~/space/skills-data/video-multi-release/config.json`（可用 `WB_SKILLS_DATA` 改根目录）。
**命令行显式传参始终优先于这里。**

| 键 | 消费者 | 作用 |
|---|---|---|
| `account` / `tag` / `theme` / `font_main` / `text_y_ratio` | `gen_cards.py` / `rebuild.sh` | 卡片默认署名、标签、主题、字体、文字位置 |
| `topics` / `hot_topics` | `release.sh` | 默认话题列表、热点开关 |
| `bgm` | `rebuild.sh` | 默认 BGM 路径 |
| `canvas_bg` / `canvas_stops` | `rebuild.sh`（`build_composition.py`） | 画布底色，暗色卡片必配 |
| `topics_history_extra` | **无脚本消费者** | 备忘用的历史题材附加话题 |
| `_canvas_dark_preset` | **无脚本消费者** | 环境变量备忘，贴到命令行才生效 |
| `image_prompt_presets.history_dark` | **无脚本消费者** | 生图提示词模板，给人生图时拼用 |

后三个属于「文档即用途」，配了不会自动生效——别以为是配错了。
