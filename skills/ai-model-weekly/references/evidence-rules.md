# 证据、日期与模型状态

## 来源的角色

优先读取模型发布方的公告、官方模型卡、API 更新日志与官方仓库。联合发布方的新闻稿也可作为一手材料。托管平台的日志可以证明在该平台上架，不能自动证明模型首次发布。

聚合目录、新闻和社交讨论用于发现候选与查找原文。厂商社区域名中用户自行发表的文章，不因域名属于厂商就自动成为官方发布声明。模型平台上需要确认发布账号属于原团队，避免使用镜像、转载或第三方量化仓库替代官方规格。

已读的一手材料可以支持后续写作，无需为了重找同一链接反复搜索。对会变化的可用性、价格与开放状态，按其影响和核实成本决定是否刷新；保存读取时间及证据边界。

页面无法读取时，尝试官方替代来源或适当的浏览器读取。仍不能建立结论，就降低确定性或放入保留线索，而不是反复搜索直到出现期望说法。不要根据标题、URL、HTTP成功或搜索摘要宣称完成正文核实。

## 每个日期都说明代表什么

| 类型 | 能证明的事情 | 常见误用 |
| --- | --- | --- |
| 官方公告日 | 当日公开宣布这一事件 | 不一定等于API上线或权重开放日 |
| 实际活动日 | 发布会或现场发布发生的日期 | 新闻稿可能晚一天发布 |
| 服务可用日 | 指定服务或API可用 | 不一定是模型首发 |
| 权重首次公开日 | 权重对外公开的日期 | 要与仓库内部提交区分 |
| 平台上架日 | 某分发或托管平台接入 | 不能当作原模型首发 |
| 论文公开日 | 报告或论文公开 | 不自动等于模型发布 |
| 提交或修改时间 | 文件发生了变动 | 不证明当时仓库已经公开，也不证明权重首次可用 |

优先选择与报道事件直接对应、证据最明确的日期。把其他有关日期作为备注保留，不强行压成一个“统一首发日”。

无时区的官方日期保留原日历日，并注明这一口径。有精确时间的记录保留原时区；需要换算时同时保留原始值。用户时区用于解释“本周”等相对日期和展示核查时间，不用于无依据地改写官方日期。

如果只能确认某日发生权重提交，就按“权重提交证据”描述，不能把标签升级成“当日首次公开发布”。日期证据不足的候选不进入“已核实首发”统计。

## 三个状态维度分开

1. 事件类型：新模型、正式版本升级、预览、开放权重、渠道接入、其他产品更新。
2. 访问条件：一般可用、需审批、需申请、研究访问、尚未可用、未知。
3. 权重状态：已公开、计划公开、闭源、未确认。

正式公告可以同时需要审批；API可用可以同时尚无公开权重；开放权重也可以带有自定义许可证。不要使用“开源”一个词覆盖所有状态。

历史公告说“下周开放”时，先保留计划状态。只有找到后续完成证据，才能升级为已公开。仅未找到后续证据时，写“本次未确认已开放”，不写成全球范围的绝对断言。

## 参数、价格与评测

- 总参数、激活参数、生成骨干参数、编码器参数分开。不要把某个组件的规模写成整个系统规模。
- 训练序列长度、服务上下文窗口、最大输出长度分别记录；“64k训练”不能推出“64k服务窗口”。
- 模态描述写清输入与输出。视频生成版本不能只因同品牌名称相近就当作通用对话旗舰。
- 价格包含币种、计费单位、输入/输出模态、缓存、上下文档位、服务商及优惠截止条件；不换用第三方价格或用token单价冒充每张图价格。
- 评测注明版本、指标、来源方与必要条件。厂商自测不是本报告实测；框架、推理预算、硬件和指标口径不同的分数不混排。
- 厂商内部复合分数或“第一”只能按其原测试范围转述，不能升级为全球综合排名。
- 不以参数规模或生成质量样例推断未测试的能力、可用性或安全性。

未披露时，使用“本次所读官方材料未披露/未确认”，并保留空值，不给出看似精确的估计。

## 从证据到文章

每个主清单事件至少有事件证据与日期证据；可以来自同一页面。参数与价格另有对应来源时分别关联。引用靠近所支持的事实，来源索引保留标题、链接、读取时间、证据用途与访问限制。

保留短摘要与必要摘录，不把全文、长期有效的排名或当前网页状态视为永久常量。趋势、分组、计算结果分别标记为分析、编辑分类、派生值。
